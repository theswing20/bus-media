# Bus Media — реклама и объявление остановок (АП №1)

Бортовой компьютер в автобусе показывает рекламу на салонных мониторах, а при подъезде к остановке
объявляет её — сначала на казахском, потом на русском. Ролики, маршруты и остановки загружаются через админку.

```
apps/server      Fastify + Prisma/Postgres: админское API, API устройств, раздача файлов, TTS для остановок
apps/admin       React + Vite: маршруты и остановки на карте, ролики, кампании, автобусы, отчёт о показах
apps/player      Electron-киоск для бортового компьютера (Linux): офлайн-кэш, GPS, геозоны, очередь озвучки
packages/shared  Общие типы + StopEngine (детерминированная логика «следующая / прибыли»)
```

## Как это работает

1. **Админка** → маршрут → клик по карте добавляет остановки (направления «туда» и «обратно» отдельно).
   На сервере для каждой остановки генерируются 4 mp3: «Келесі аялдама — X», «Аялдама — X»,
   «Следующая остановка — X», «Остановка — X». TTS — ElevenLabs (`eleven_v3`/`eleven_v4`: только они знают казахский)
   или Azure Speech, см. `TTS_PROVIDER` в `.env`. Файлы называются хэшем голоса и текста: смена голоса = новый URL,
   борта скачают заново, а уже озвученные фразы повторно не генерируются. После смены голоса —
   `POST /api/admin/routes/:id/regenerate-audio`. Без TTS озвучку можно записать диктором и положить файлы руками.
2. **Кампания** = ролики × маршруты × период. Автобус привязан к маршруту, поэтому получает только свои кампании.
3. **Плеер** при старте читает манифест из кэша и сразу играет. Раз в `syncIntervalSec` спрашивает сервер;
   если версия манифеста изменилась — докачивает файлы и только потом переключается. Без сети живёт на старом.
4. **GPS** (gpsd ← модем Quectel EC25) → `StopEngine`: направление определяется по последовательности пройденных
   остановок; за `approachDistanceM` до следующей — «approach», в радиусе `radiusM` — «arrive». На время объявления
   реклама приглушается до `duckVolume`, снизу экрана — плашка с названием остановки.
5. Каждый показ пишется в локальный JSONL и раз в минуту уходит на сервер пачкой (идемпотентно по uuid).
   Отчёт «сколько раз, на каких маршрутах, когда» — вкладка «Отчёты».
6. **Датчики пассажиров** (`PLAYER_PAX`) → плеер ведёт заполненность салона и пишет каждое «вошло/вышло» с привязкой
   к остановке. Из этого считаются: пассажиропоток по остановкам/часам/бортам, пик заполненности, текущая заполненность
   борта (вкладка «Автобусы») и **аудитория каждого показа** = было в салоне на старте ролика + вошло во время него.
   Модель датчиков ещё не выбрана: в режиме `http` плеер принимает события по локальной сети
   (`POST http://<борт>:8787/count`, тело `{"door":1,"in":2,"out":0}` или массив таких объектов) — конкретный датчик
   подключается переходником к этому формату. На конечной заполненность сбрасывается в 0, чтобы ошибка счёта не копилась.

## Запуск для разработки

```bash
pnpm install
cp .env.example .env               # поправить ADMIN_TOKEN; ключ TTS (ElevenLabs/Azure) — по желанию
docker compose up -d               # Postgres
pnpm db:migrate                    # создать таблицы
pnpm --filter @bus/server seed     # тестовый маршрут TEST + борт A700 (выведет токен устройства)

pnpm dev:server                    # http://localhost:4000
pnpm dev:admin                     # http://localhost:5173, токен — ADMIN_TOKEN

# плеер в режиме mock-GPS (едет по остановкам маршрута без железа):
cp .env apps/player/.env           # вписать PLAYER_DEVICE_ID / PLAYER_DEVICE_TOKEN из seed, PLAYER_GPS=mock, PLAYER_PAX=mock, PLAYER_KIOSK=0
pnpm dev:player
```

## Бортовой компьютер (Ubuntu Server, X11)

Ставить **Ubuntu Server** (22.04 LTS предпочтительно; на 24.04 Electron нужен `--no-sandbox`, он уже в `xinitrc`).
Ubuntu Desktop не подходит: GNOME на Wayland ломает клонирование мониторов через xrandr и спорит с нашим `startx`.
`deploy/prepare-image.sh` готовит «золотой» образ для клонирования на все борта: ставит плеер, отключает GDM,
прячет NMEA-порт EC25 от ModemManager, поднимает 4G через NetworkManager, настраивает watchdog.

```bash
pnpm --filter @bus/player package:linux   # → apps/player/dist/*.deb
# на борту:
cd apps/player/deploy && sudo ./install.sh
sudo nano /etc/bus-player/player.env      # PLAYER_SERVER_URL, PLAYER_DEVICE_ID, PLAYER_DEVICE_TOKEN
sudo systemctl start bus-player
```

- `xinitrc` клонирует второй монитор на первый через xrandr и запускает плеер в киоске.
- GPS берётся из gpsd (`/dev/ttyUSB1` у EC25 — проверить `ls /dev/ttyUSB*`). Для чтения NMEA напрямую:
  `PLAYER_GPS=serial` и `pnpm --filter @bus/player add serialport @serialport/parser-readline`.
- Звук идёт в салонный усилитель с линейного выхода компьютера; громкость рекламы/объявлений — в настройках устройства
  (`settings` в админке → `adVolume`, `announceVolume`, `duckVolume`, `approachDistanceM`).
